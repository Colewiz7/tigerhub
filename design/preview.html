One seed, then roles.

The design system behind TigerHub, pulled out so it can go somewhere else. Every colour here was generated from a single brand hex by Material 3's algorithm, which is the whole trick: you never pick a second colour, so nothing can clash. Examples are drawn as a camera monitor, because that is what it is going into next.

Palette

Roles, never hexes

Never write a hex in a component. The reason a scheme holds together is that every surface has a matching on- colour guaranteed to be readable against it. Note that the seed itself, #F76902, appears nowhere below. A seed is an input, not a swatch.

The surface ramp is how you express depth. Page on surface, cards a step up, things inside cards a step above that. Reach for a border only when the ramp genuinely is not enough.

Status

Colour that means something, and never travels alone

Status colour is a separate set from the accent and from any categorical palette. It never gets reused for "series 4". Three states is usually all you need; here they read as a camera's.

Categorical

Telling N things apart

For charts, zones, or motion-event types. Assign in fixed order and never cycle: a fifth category is not a generated hue, it folds into "Other" or earns its own view. Colour follows the entity, not its rank, so filtering one out must not repaint the survivors.

cat-1people
cat-2vehicles
cat-3animals
cat-4packages

Validated, not guessed: worst adjacent pair dE 18.8 in deuteranopia in light and 19.7 in protanopia in dark. Change them and re-validate rather than trusting your eyes.

Shape

Nothing is rounded at 8 or below

That single rule does most of the work of making it look deliberate.

Chips and status indicators are full pills, not slightly rounded rectangles. Outer containers get 30, anything nested inside one gets 20, so the nesting reads as nesting.

The key number on a card is oversized and light. Everything else recedes. Labels under big numbers are small, muted and wide tracked. Do not bold body text to make it matter, make the thing next to it quieter instead.

Take it with you

The whole thing, as CSS variables

/* light is the bare :root; dark redefines only the tokens */
:root {
  --primary: #8d4e2c;      --on-primary: #ffffff;
  --surface: #fff8f6;      --on-surface: #221a16;
  --surface-container-low: #fff1eb;
  --outline: #85736c;      --outline-variant: #d7c2b9;
  --ok: #589b44;  --warn: #996100;  --bad: #782f28;
  --radius-card: 30px;     --radius-pill: 999px;
}

/* guarded so an explicit light choice still beats a dark OS */
@media (prefers-color-scheme: dark) {
  :root:not([data-theme="light"]) {
    --primary: #ffb693;    --on-primary: #542104;
    --surface: #1a120e;    --on-surface: #f0dfd8;
    --ok: #8bd376;  --warn: #ffddb7;  --bad: #c46a61;
  }
}

The full set, both themes, every role, is in design/tokens.css in the repo, with tokens.json for anything that is not CSS and STYLE.md for the reasoning. All three are generated from the app's real theme rather than transcribed, so they cannot drift.

Hard-won

Four things that will bite you

  • →Test at phone width with real content. An empty state is the one layout that cannot overflow, so testing empty proves nothing. This exact mistake passed cleanly and hid three real bugs.
  • →Test at 2x text size. Every fixed-height row in TigerHub overflowed at 1.3x. Fixed heights and user text sizes are fundamentally in tension: scale the container, or cap the text inside a fixed shape, but decide which.
  • →Fixed shapes need their text capped. A number inside a circle cannot grow with the system font, or it leaves the circle.
  • →Measure contrast against the surface it actually sits on, not against white. A 1.2:1 fill is invisible however good the swatch looked on its own.
Every colour on this page is a live CSS variable from the set described. Switch your system theme and the whole thing re-resolves, which is the point.
